01 — Definición

¿Qué son y en qué se diferencian?

lowerCamelCase

miVariable

La primera palabra va en minúscula. Cada palabra siguiente empieza con mayúscula.

También llamado: camelCase o dromedaryCase

UpperCamelCase

MiVariable

Todas las palabras, incluida la primera, empiezan con mayúscula.

También llamado: PascalCase

Ambos estilos eliminan espacios y caracteres especiales entre palabras. La diferencia es únicamente la capitalización de la primera letra. Esta convención permite leer identificadores de varias palabras sin ambigüedad.

02 — Contextos

¿Cuándo usar cada uno?

Elemento Convención Ejemplo
Variable lowerCamelCase edadUsuario
Función / Método lowerCamelCase calcularPrecio()
Parámetro lowerCamelCase nombreCliente
Clase UpperCamelCase CuentaBancaria
Interfaz UpperCamelCase IServicioEmail
Enum / Tipo UpperCamelCase EstadoPedido

La lógica es simple: lowerCamelCase para valores y acciones (variables, funciones), UpperCamelCase para plantillas y tipos (clases, interfaces). Así puedes identificar de qué se trata un identificador con solo ver su primera letra.

03 — Ejemplos comparativos

Código en 3 lenguajes

JavaScript / TypeScript
// Variables y funciones → lowerCamelCase
let nombreCompleto = "Ana López";
const precioConDescuento = 99.9;

function calcularImpuesto(precio) {
  return precio * 0.19;
}

// Clases e interfaces → UpperCamelCase
class CuentaBancaria {
  constructor(saldoInicial) { ... }
  depositar(monto) { ... }
}

interface IServicioEmail {
  enviar(destinatario: string): void;
}
Java
// Variables y métodos → lowerCamelCase
String nombreCompleto = "Ana López";
int edadUsuario = 25;

public void calcularImpuesto(double precio) {
  return precio * 0.19;
}

// Clases → UpperCamelCase
public class CuentaBancaria {
  private double saldoActual;
  public void depositar(double monto) { ... }
}
Python
# Python usa snake_case para variables y funciones,
# pero mantiene UpperCamelCase para clases (igual que los demás)

nombre_completo = "Ana López"   # snake_case (convención Python)

    return precio * 0.19

class CuentaBancaria:             # UpperCamelCase (universal)
    def __init__(self, saldo):
        self.saldo_actual = saldo

04 — Casos especiales

Siglas, acrónimos y números

lowerCamelCase

urlBase ✓ correcto
URLBase ✗ evitar
httpRequest ✓ correcto
userId ✓ correcto

HttpRequest ✓ correcto
HTTPRequest ✗ evitar
UserId ✓ correcto
UrlBase ✓ correcto

Letras griegas

deltaVelocidad✓
betaVersion✓
ΔVelocidad✗

Se escribe el nombre de la letra en inglés, no el símbolo.

Números en identificadores

Los identificadores no pueden empezar con número.

05 — Preguntas frecuentes

Cuatro preguntas clave

01  ¿Por qué las clases usan UpperCamelCase y no lowerCamelCase? ▼
Las clases representan plantillas o tipos para crear objetos, no valores concretos. Al usar UpperCamelCase se distinguen visualmente de variables y funciones con solo mirar la primera letra: new CuentaBancaria() vs calcularSaldo(). Es una señal visual que dice "esto es un tipo, no un dato".
02  ¿Cómo se escribe un identificador con una sigla como 'URL' en Camel Case? ▼
La recomendación moderna (Google, Microsoft) es tratar la sigla como una palabra normal: urlBase en lower, UrlBase en upper. Evita URLBase porque dificulta leer dónde termina la sigla y empieza la siguiente palabra. Esto puede variar según la guía de estilo del proyecto.
03  ¿Cuándo es aceptable usar una sola palabra sin mayúsculas internas? ▼
Siempre que el identificador sea una sola palabra real: nombre, precio, usuario. No hay nada que capitalizar porque no hay segunda palabra. En UpperCamelCase sería Nombre, Precio. No es un error, simplemente el estilo no se nota con una sola palabra.
04  ¿Qué pasa si el nombre empieza con una sigla en lowerCamelCase? ▼
La sigla completa va en minúscula al inicio: urlBase, idUsuario, httpCliente. Si la sigla aparece en el interior, solo la primera letra sube: baseUrl, obtenerHttpCliente(). Esto mantiene la coherencia visual del camelCase.
